# เปิดขายจริง — ทำตามลำดับ

เว็บบน Railway ปิดโหมดทดสอบแล้ว (`PROVIDERS=hubzell,wepay`) — ระหว่างที่ยังไม่ใส่คีย์ร้าน หน้าเว็บขึ้นว่า
"ระบบเติมเงินยังไม่พร้อมให้บริการ" และลูกค้าทำรายการไม่ได้ (ไม่มีการตัดเงินใดๆ) ทำครบตามนี้แล้วเติมได้จริงทันที

> ติดตั้งระบบใหม่ที่อื่น: ค่าเริ่มต้นคือโหมดทดสอบ (`PROVIDERS=mock,mock2` — ร้านจำลอง) ระหว่างนั้น **ห้ามรับเงินลูกค้าจริง**

หลังบ้าน → แดชบอร์ด → กล่อง **"พร้อมเปิดร้านหรือยัง?"** บอกว่ายังขาดอะไร (อัปเดตเองทุกครั้งที่เปิดหน้า)

---

## 1. บัญชี Railway

- **ชำระบิลที่ค้าง** — Railway → รูปโปรไฟล์ → Workspace Settings → **Billing** → Pay Invoice
  บิลค้างนานเกินไป Railway จะปิดบริการทุกโปรเจกต์ในบัญชี
- **อัปเกรดเป็นแผน Pro** (Plans → Upgrade to Pro) — จำเป็นเพราะ:
  - ร้าน HubZell / wePAY รับคำขอเฉพาะจาก IP ที่ลงทะเบียนไว้ → ต้องใช้ **Static Outbound IPs** ซึ่งมีเฉพาะแผน Pro
    (แผน Hobby ไม่มี IP ขาออกคงที่ ร้านจะปฏิเสธทุกรายการ)
  - ได้ระบบสำรองฐานข้อมูลอัตโนมัติของ Railway (หน้า Postgres → Backups)
- บริการ **trueais → Settings → Networking → Enable Static IPs** → จด IP ที่ Railway แสดง **ทุกตัว** (ปกติ 3 ตัว) → กด Deploy

> ตั้งไว้แล้ว ไม่ต้องทำซ้ำ: Healthcheck Path = `/api/health` และ `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=40`
> (ให้เวลาระบบส่งรายการที่ค้างอยู่ให้เสร็จก่อนปิดตอน deploy — ถ้าไม่มี รายการที่กำลังส่งจะค้าง "ไม่ทราบผล")

## 2. ขอ API จากร้าน

ใช้ร้านเดียวหรือทั้งสองร้านก็ได้

| | HubZell | wePAY |
|---|---|---|
| ขายได้ | เติมเงิน + แพ็กเกจเน็ต | เติมเงินอย่างเดียว (เฉพาะยอดที่ wePAY รับ เช่น dtac ไม่เกิน 800 บาท) |
| สมัคร | HubZell Reseller Console (shop.hubzell.com) แล้วรอ **KYC ผ่าน** | ติดต่อ wePAY (โทร 02-965-5553 / LINE @wepay) ขอเปิดใช้ API |
| ได้มา | API key + Secret key (หน้า Developer) | ชื่อผู้ใช้ + รหัสผ่านสำหรับ API |
| ลงทะเบียน IP | หน้า Developer → **IP Whitelist** ใส่ IP ทุกตัวจากข้อ 1 | แจ้ง IP ทุกตัวจากข้อ 1 ให้ wePAY |
| Callback | หน้า Developer → Callback URL = URL จากหลังบ้าน → ผู้ให้บริการ & ร้าน → HubZell | ระบบแนบให้เองกับทุกรายการ ไม่ต้องตั้ง |

รายละเอียด: [HUBZELL-INTEGRATION.md](HUBZELL-INTEGRATION.md) · [WEPAY-INTEGRATION.md](WEPAY-INTEGRATION.md)

## 3. ใส่คีย์ร้านในหลังบ้าน (ไม่ต้องแก้ Railway — ทำเองเท่านั้น อย่าส่งคีย์/รหัสผ่านให้ใครทางแชต)

1. ล็อกอิน `/admin` ครั้งแรก: อีเมลตาม `ADMIN_EMAIL` + รหัสผ่านที่ระบบสุ่มให้ (Railway → trueais → Deployments → deploy แรก → View logs → บรรทัด "รหัสผ่าน :")
   → **เปลี่ยนรหัสผ่าน** แล้ว **เปิดยืนยันตัวตน 2 ชั้น** (หน้า "บัญชีของฉัน") ก่อนใส่คีย์ร้าน
2. **ผู้ให้บริการ & ร้าน** → การ์ดของร้าน → ปุ่ม **"ใส่คีย์ร้าน"** → วางค่าที่ได้จากข้อ 2 → **"บันทึกและทดสอบการเชื่อมต่อ"**
   (ระบบขอรหัสผ่านแอดมินของคุณอีกครั้งก่อนบันทึก)

   | ร้าน | ช่องที่ต้องใส่ |
   |---|---|
   | HubZell | API Key + Secret Key (หน้า Developer) · Webhook signing secret ไม่ต้องใส่ถ้าใช้ Callback URL |
   | wePAY | ชื่อผู้ใช้ API + รหัสผ่าน API + **เงินคืน (%)** แต่ละเครือข่ายตามหน้า "บริการ" ของ wePAY (ระบบใช้คิดต้นทุน) |

3. ดูผลทันทีหลังกดบันทึก:
   - **"เชื่อมต่อสำเร็จ · เครดิตคงเหลือ ฿..."** = คีย์ถูกและ IP ลงทะเบียนแล้ว ร้านนี้ขึ้นให้ลูกค้าเลือกทันที (ไม่ต้อง Deploy / รีสตาร์ท)
   - **"ยังเชื่อมต่อไม่สำเร็จ"** = ตรวจคีย์ หรือ IP ยังไม่ได้ลงทะเบียน (ข้อ 1–2) — ระบบพักร้านนี้ไว้ ไม่ส่งรายการ และเช็กให้เองทุก 5 นาที
     แก้แล้วกด **"เช็กเครดิต"** หรือใส่คีย์ใหม่ทับ

ใส่เฉพาะร้านที่ได้คีย์แล้วก็ได้ — ร้านที่ยังไม่มีคีย์ระบบข้ามไปเอง (ลูกค้าไม่เห็นร้านนั้น)
ใช้ wePAY อย่างเดียว = หน้าเว็บลูกค้าซ่อนเมนูแพ็กเกจเน็ตให้อัตโนมัติ (เปิดเองเมื่อมีร้านที่ขายแพ็กเกจ)

> **ความปลอดภัยของคีย์:** เก็บแบบเข้ารหัสในฐานข้อมูล — หลังบันทึกแล้วไม่มีใครเห็นคีย์เต็มอีก (หน้าเว็บแสดงแค่ "ใส่แล้ว" + 4 ตัวท้าย)
> กุญแจเข้ารหัสอยู่ในไฟล์ `data/credentials.key` บน Volume ของ Railway (ระบบสร้างให้เอง ห้ามลบ) แยกจากฐานข้อมูล
> ไฟล์สำรองฐานข้อมูลจึงไม่มีคีย์ที่อ่านได้ — ย้ายไปเครื่องใหม่หรือกู้จากไฟล์สำรอง ให้ใส่คีย์ร้านใหม่ในหลังบ้าน (ระบบเตือนให้เอง)
> ทุกครั้งที่มีการเปลี่ยนคีย์ ระบบบันทึกใน Log และแจ้งเตือน LINE / Telegram
>
> ใส่ผ่าน Railway Variables แบบเดิมก็ยังได้ (`HUBZELL_API_KEY` ฯลฯ) — ถ้าใส่ทั้งสองที่ ระบบใช้ค่าในหลังบ้านก่อน

`PROVIDERS` ตั้งไว้แล้วใน Railway เป็น `hubzell,wepay` (เรียงร้านหลักก่อน) — แก้เฉพาะถ้าต้องการใช้ร้านเดียว เช่น `wepay`
(ลำดับ/ปิดร้านชั่วคราว แก้ได้ในหลังบ้าน) ห้ามมี `mock` ปนกับร้านจริง (ระบบจะไม่ยอมเปิด)

## 4. ตั้งค่าอื่นในหลังบ้าน (`/admin`)

1. **ตั้งค่า → ช่องทางรับเงิน**: ใส่พร้อมเพย์ (หรือบัญชีธนาคาร) → กด **"ทดสอบ QR 1 บาท"** สแกนด้วยแอปธนาคาร ตรวจว่าชื่อผู้รับถูกต้อง (ไม่ต้องโอนจริง)
2. **ตั้งค่า → ช่องทางติดต่อร้าน**: LINE / เบอร์โทร
3. HubZell: **ผู้ให้บริการ & ร้าน** → กด **"ดึงรายการ"** แล้วจับคู่ยอดเติมเงิน/แพ็กเกจที่จะขาย
4. แท็บ **ราคาแต่ละร้าน**: ตั้งส่วนลดให้ลูกค้าของแต่ละร้าน (ระบบไม่ยอมให้ตั้งส่วนลดจนขายต่ำกว่าต้นทุน)
5. **สินค้า & เครือข่าย** → ลบแพ็กเกจตัวอย่าง
6. (แนะนำ) **ตั้งค่า → แจ้งเตือนแอดมิน → "ตั้งค่าแจ้งเตือน"** → ใส่ token ของ Telegram (Bot token + Chat ID) หรือ LINE
   แล้วกด **"ส่งข้อความทดสอบ"** — จะได้รู้ทันทีเมื่อมีสลิปรออนุมัติ รายการต้องตรวจ หรือมีคนเปลี่ยนคีย์ร้าน (วิธีขอ token ใน README)

## 5. ทดสอบด้วยเงินจริงยอดเล็ก (ก่อนบอกลูกค้า)

1. สมัครบัญชีลูกค้าใหม่ (คนละบัญชีกับแอดมิน)
2. กระเป๋าเงิน → เติม 20 บาท ผ่านพร้อมเพย์ → แนบสลิป → อนุมัติในหลังบ้าน → ยอดเข้ากระเป๋า
3. เติมเงินมือถือ **เบอร์ตัวเอง 10 บาท ทีละร้าน** → ต้องได้ SMS เงินเข้าจริง และรายการขึ้น "สำเร็จ"
4. แดชบอร์ด → "พร้อมเปิดร้านหรือยัง?" ต้องไม่เหลือข้อ **ต้องแก้**

## 6. หลังเปิดขาย

- ดูรายการ **"ต้องตรวจสอบ"** และสลิปรออนุมัติทุกวัน
- เติมเครดิตที่ร้าน (HubZell / wePAY) ก่อนหมด — ระบบเตือนเมื่อต่ำกว่าที่ตั้งไว้
- **ดาวน์โหลดไฟล์สำรองเก็บนอก Railway ทุกสัปดาห์** (หลังบ้าน → ตั้งค่า → สำรองข้อมูล) — ระบบสำรองให้วันละครั้งบน Volume แต่ถ้าบัญชี Railway มีปัญหา ไฟล์นั้นหายไปด้วย
- เปลี่ยนคีย์ร้านเมื่อสงสัยว่ารั่ว: สร้างคีย์ใหม่ที่ร้าน → หลังบ้าน → ผู้ให้บริการ & ร้าน → **"แก้คีย์ร้าน"** → วางคีย์ใหม่ทับ (ใช้ได้ทันที)
