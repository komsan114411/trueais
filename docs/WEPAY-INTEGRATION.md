# วิธีเชื่อมต่อร้าน wePAY

wePAY (<https://www.wepay.in.th>) เป็นผู้ให้บริการเติมเงินมือถือแบบใช้กระเป๋าเงินล่วงหน้า (ได้เงินคืนเป็น % ของยอดเติม)
ระบบนี้เพิ่ม wePAY เป็น **ร้านหนึ่งที่ลูกค้าเลือกได้** ใช้ร่วมกับ HubZell / WonDD ได้ — ถ้า wePAY ไม่รับรายการ (เช่น เครดิตหมด)
ระบบ **ส่งต่อร้านอื่นให้อัตโนมัติในราคาเดิม** เฉพาะกรณีที่มั่นใจว่า wePAY ยังไม่ได้ทำรายการ

- รองรับ: **เติมเงิน** AIS (10–1,500 บาท), dtac (10–800 บาท), TrueMove H (5–1,000 บาท) — ยอดนอกช่วงไม่แสดงในร้านนี้
- ยังไม่รองรับ: แพ็กเกจเน็ต (wePAY ระบุแพ็กเกจด้วยราคาแทนรหัส ต้องรอยืนยันจากคู่มือจริง) — ลูกค้าซื้อแพ็กเกจผ่านร้านอื่นได้ตามปกติ

> ⚠️ **wePAY ไม่เผยแพร่คู่มือ API สาธารณะ** ไฟล์ `src/providers/wepay.js` ทำตามรูปแบบที่ใช้กันจริง
> เมื่อ wePAY ส่งคู่มือ ("wePAY API Document") ให้ ตรวจจุดที่มีป้าย `[CHECK]` ในไฟล์นั้น
>
> ⚠️ **ทุกรายการเป็นของจริงและตัดเครดิตจริง** — ทดสอบด้วยยอดเล็กที่สุดก่อนเปิดขาย

---

## ขั้นตอนเปิดใช้

### 1. ขอเปิด API กับ wePAY
1. สมัครสมาชิก wePAY แล้วติดต่อขอใช้ API สำหรับร้านค้า (Call Center 02-965-5553 เวลา 08:30–20:00 หรือ LINE `@wepay`)
2. wePAY จะให้ **ชื่อผู้ใช้สำหรับ API** (ใช้คู่กับรหัสผ่านบัญชี)
3. **แจ้ง IP ขาออกของเซิร์ฟเวอร์** ให้ wePAY ลงทะเบียน — ถ้ายังไม่ลงทะเบียน ทุกคำขอจะถูกปฏิเสธ (รหัส 20005)
   ต้องใช้เซิร์ฟเวอร์ที่ IP ขาออกคงที่ (VPS หรือบริการที่มี Static Outbound IP)
4. เติมเงินเข้ากระเป๋า wePAY (โอนธนาคาร / 7-Eleven แล้วแจ้งโอน)
5. ขอคู่มือ API และอัตราเงินคืนของบัญชีคุณ (สมาชิกประเภทร้านค้าได้เงินคืนสูงกว่าสมาชิกทั่วไป)

### 2. ใส่ค่าใน `.env` (หรือ Variables ของ Railway)
```ini
PROVIDERS=hubzell,wepay
WEPAY_USERNAME=ชื่อผู้ใช้ที่ wePAY ให้
WEPAY_PASSWORD=รหัสผ่าน
# เงินคืน (%) ของบัญชีคุณต่อเครือข่าย — ใช้คิดต้นทุน กันขายขาดทุน
WEPAY_DISCOUNTS=AIS:1,DTAC:3,TRUE:3
```
- รหัสผ่านไม่ถูกส่งตรงๆ — ระบบส่งเฉพาะค่า MD5 ตามที่ wePAY กำหนด
- ต้นทุนแต่ละรายการ = ยอดเติม − เงินคืนตาม `WEPAY_DISCOUNTS` — ระบบบันทึกยอดที่ wePAY ตัดจริง (`total_amount`) ทุกรายการ
  และแจ้งเตือนแอดมินถ้ายอดที่ตัดจริงสูงกว่าราคาขาย (แปลว่าอัตราที่ตั้งสูงกว่าที่ได้จริง)
- ส่วนลดลูกค้าของร้าน wePAY (หน้าแอดมิน → ผู้ให้บริการ & ร้าน → ร้าน) ตั้งได้ไม่เกินเงินคืนนี้
- `PUBLIC_URL` ต้องเป็น `https://` ที่เปิดจากอินเทอร์เน็ตได้ — wePAY แจ้งผลรายการกลับมาที่ที่อยู่นี้

แก้แล้วเปิดระบบใหม่ → หน้าแอดมิน → **ผู้ให้บริการ & ร้าน** ต้องเห็น wePAY "พร้อม" และเครดิตคงเหลือ

### 3. ทดสอบด้วยยอดเล็ก
1. ปิดร้านอื่นชั่วคราว (ตั้งค่า → "ปิดใช้ผู้ให้บริการชั่วคราว") หรือเลือกร้าน wePAY ตอนสั่ง
2. เติมเงินเบอร์ของคุณเอง 10 บาท → รายการควรเป็น "กำลังดำเนินการ" แล้วเปลี่ยนเป็น "สำเร็จ" ภายใน 1–5 นาที
3. ตรวจในหน้า wePAY ว่ามีรายการเดียว และยอดที่ตัดตรงกับต้นทุนในหน้ารายการ (แอดมิน → รายการ → เปิดรายการ)
4. ลองแต่ละเครือข่ายที่จะขาย แล้วค่อยเปิดร้านอื่นกลับ

## ระบบทำงานอย่างไร

| เหตุการณ์ | ระบบทำอะไร |
|---|---|
| wePAY ตอบ `00000` + เลขที่รายการ | รับรายการแล้ว → รอผล (callback) และเช็กสถานะด้วย `get_output` ตามรอบ |
| wePAY แจ้งผลกลับ (callback) | **ไม่เชื่อทันที** — เช็กสถานะกับ wePAY ซ้ำก่อนเสมอ แล้วจึงบันทึกผล/คืนเงิน (คืนเงินได้ครั้งเดียว) |
| สถานะ 2 | สำเร็จ |
| สถานะ 4 | ไม่สำเร็จ (wePAY คืนเงินเข้ากระเป๋า wePAY) → คืนเงินลูกค้าอัตโนมัติ |
| รหัสปฏิเสธที่แน่ชัด (เครดิตไม่พอ 30019, IP ยังไม่ลงทะเบียน 20005, รหัสผ่านผิด 20001, ยอด/เบอร์ไม่ถูกต้อง ฯลฯ) และไม่มีเลขที่รายการ | ยังไม่ได้ทำรายการแน่นอน → ส่งต่อร้านอื่นในราคาเดิม · ปัญหาบัญชี/เครดิต → พักร้าน wePAY ชั่วคราว |
| หมดเวลารอ / HTTP 5xx / คำตอบที่อ่านไม่ออก / รหัสที่ไม่รู้จัก / ไม่มีเลขที่รายการ | **ไม่รู้ผล** → ไม่คืนเงิน ไม่ส่งร้านอื่น ไม่ส่งซ้ำ — รอ wePAY แจ้งผล แล้วเช็กยืนยัน ถ้าครบเวลายังไม่รู้ผล ส่งให้แอดมินตรวจ |
| เลขที่รายการซ้ำ (30016) | อาจรับรายการไปแล้ว → ส่งให้แอดมินตรวจในหน้า wePAY |

- เลขที่รายการของเรา (เช่น `TP261102AB12CD34`) ส่งเป็น `dest_ref` — ตรงกับที่เห็นในหน้า wePAY ใช้ค้นได้ทันที
- ที่อยู่รับผล (callback) มีรหัสลับต่อท้าย `?t=...` — คำขอที่ไม่มีรหัสนี้ถูกปฏิเสธ (wePAY ไม่มีลายเซ็น)
  ถ้า wePAY แจ้ง IP ที่ใช้ส่งผล ใส่ใน `WEPAY_CALLBACK_IPS` เพื่อรับเฉพาะจาก IP นั้น
- ทุกคำขอ/คำตอบบันทึกใน หน้าแอดมิน → Log → การเชื่อมต่อ (ซ่อนรหัสผ่าน)

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| wePAY ถูกพัก "IP ของเซิร์ฟเวอร์ยังไม่ได้ลงทะเบียน" | แจ้ง IP ขาออกของเซิร์ฟเวอร์ให้ wePAY (ถ้าใช้ Railway ต้องเปิด Static Outbound IP ก่อน) |
| "ชื่อผู้ใช้หรือรหัสผ่าน wePAY ไม่ถูกต้อง" | ตรวจ `WEPAY_USERNAME` / `WEPAY_PASSWORD` (ชื่อผู้ใช้สำหรับ API อาจไม่ใช่ชื่อที่ใช้ล็อกอินหน้าเว็บ) |
| "เครดิตในกระเป๋า wePAY ไม่พอ" | เติมเงินกระเป๋า wePAY — ระหว่างนี้รายการใหม่ไปร้านสำรองให้อัตโนมัติ |
| รายการค้าง "รอ wePAY แจ้งผลกลับ" | คำขอส่งหมดเวลารอ ระบบยังไม่มีเลขที่รายการของ wePAY — ตรวจ `PUBLIC_URL` (ต้องเปิดจากอินเทอร์เน็ตได้) หรือค้นเลขที่รายการในหน้า wePAY แล้วยืนยันผลเองในหน้ารายการ |
| แจ้งเตือน "ตัดเงินสูงกว่าราคาขาย" | อัตราใน `WEPAY_DISCOUNTS` สูงกว่าที่บัญชีได้จริง หรือส่วนลดลูกค้าของร้าน wePAY สูงเกิน — แก้ให้ตรง |
