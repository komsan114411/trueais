# วิธีเชื่อมต่อ HubZell + ใช้หลายร้านพร้อมกัน

HubZell (บริษัท วัน สยามซอฟท์ จำกัด) มี API ที่เปิดให้ใช้จริง พร้อมคู่มือที่ <https://shop.hubzell.com/docs>
ระบบนี้เชื่อม HubZell ตามคู่มือแล้ว ใช้ร่วมกับ WonDD ได้ ลูกค้า **เลือกร้านเองได้** และถ้าร้านที่เลือกไม่รับรายการ ระบบ **ส่งต่อร้านอื่นให้อัตโนมัติในราคาเดิม**

> ⚠️ **HubZell ไม่มี sandbox** — ทุกรายการเป็นของจริงและตัดเครดิตจริง ทดสอบด้วยยอดเล็กที่สุดก่อนเปิดขายเสมอ

## ขั้นตอนเปิดใช้

### 1. สมัครและยืนยันตัวตนกับ HubZell
1. สมัครตัวแทนที่ <https://shop.hubzell.com/register> (บุคคล: บัตรประชาชน / นิติบุคคล: หนังสือรับรองบริษัท)
2. รอ **KYC ผ่าน** ก่อน — ถ้ายังไม่ผ่าน HubZell จะปฏิเสธการสั่งซื้อ และถ้าโดนซ้ำ 5 ครั้งใน 5 นาทีจะ **บล็อก IP 24 ชั่วโมง**
   (ระบบนี้หยุดส่งไป HubZell ทันทีตั้งแต่ครั้งแรกที่เจอปัญหานี้ เพื่อไม่ให้โดนบล็อก)
3. เติมเครดิต (THB) ใน HubZell

### 2. ตั้งค่าที่หน้า Developer ใน Reseller Console
- **IP Whitelist (บังคับ):** เพิ่ม IP ขาออกของเซิร์ฟเวอร์ที่รันระบบนี้ — ถ้า whitelist ว่าง ทุกคำขอจะถูกปฏิเสธ
  (ต้องใช้เซิร์ฟเวอร์ที่มี IP คงที่ เช่น VPS)
- **Callback URL:** ใส่ URL จากหน้าแอดมิน → ผู้ให้บริการ & ร้าน → HubZell (ต้องเป็น https และเข้าถึงได้จากอินเทอร์เน็ต)
  ระบบตรวจลายเซ็น `X-Hubzell-Signature` ทุกครั้ง ถ้าลายเซ็นผิดหรือเวลาเก่าเกิน 5 นาที จะปฏิเสธ
- คัดลอก **API key** และ **secret key**

### 3. ใส่ค่าใน `.env`
แก้บรรทัดเดิมที่มีอยู่แล้วในไฟล์ `.env` (ไม่ต้องเพิ่มบรรทัดใหม่ซ้ำ — ถ้ามีชื่อเดียวกัน 2 บรรทัด ระบบใช้บรรทัดล่างสุดและเตือนตอนเปิด)
```ini
# ใช้ HubZell อย่างเดียว (แนะนำตอนนี้ ระหว่างที่ WonDD ยังไม่เปิด API)
PROVIDERS=hubzell
# ใส่ในหลังบ้านได้เลย (ผู้ให้บริการ & ร้าน → การ์ด HubZell → "ใส่คีย์ร้าน") — ไม่ต้องใส่ 2 บรรทัดนี้
HUBZELL_API_KEY=...
HUBZELL_SECRET_KEY=...
```
เมื่อ WonDD พร้อมแล้ว เปลี่ยนเป็น `PROVIDERS=hubzell,wondd` (เรียงตามลำดับความสำคัญ — เจ้าแรกถูกเลือกก่อน)

ปิด-เปิดระบบใหม่ แล้วดูหน้าแอดมิน → **ผู้ให้บริการ & ร้าน** ต้องเห็น HubZell "พร้อมใช้" และกด **เช็กเครดิต** แล้วเห็นยอดถูกต้อง
(ถ้า key ผิด / IP ไม่อยู่ใน whitelist ระบบจะแจ้งและพัก HubZell ไว้เอง)

### 4. ดึงรายการบริการ แล้วจับคู่
HubZell ขายเป็น "บริการราคาคงที่" (1 ยอดเติม = 1 รหัสบริการ) จึงต้องจับคู่ยอด/แพ็กเกจของเรากับบริการของ HubZell ก่อน
1. กด **ดึงรายการ** — ระบบดึงหมวด MOBILE_TOPUP มาให้ พร้อมบอกว่ารายการไหนใช้ได้/ไม่ได้ (ใช้ได้เฉพาะที่กรอกแค่เบอร์โทร 1 ช่อง)
2. กด **จับคู่** ที่แต่ละบริการ — ระบบเดาเครือข่าย/ยอดจากชื่อให้ ตรวจให้ถูกแล้วบันทึก
3. **การจับคู่ปิดไว้เสมอจนกว่าจะกดเปิดใช้** และเปิดไม่ได้ถ้าต้นทุนสูงกว่าราคาที่ขายลูกค้า (กันขาดทุน)
4. แพ็กเกจเน็ต: กด **สร้างเป็นแพ็กเกจใหม่** จากบริการของ HubZell (สร้างแบบปิดขายไว้ก่อน ตรวจราคาแล้วค่อยเปิด)
5. กด **ดึงรายการ** เป็นระยะ: ถ้า HubZell ขึ้นราคาจนขาดทุน หรือเลิกขายบริการไหน ระบบ **ปิดการจับคู่นั้นให้อัตโนมัติ + แจ้งเตือน**

### 5. ตั้งราคาของแต่ละร้าน
หน้าแอดมิน → ผู้ให้บริการ & ร้าน → **ราคาแต่ละร้าน**
- ตั้ง **ชื่อร้าน** ที่ลูกค้าเห็นได้
- ตั้ง **ส่วนลดลูกค้า** แยกตามเครือข่าย (ไม่ตั้ง = ใช้ส่วนลดมาตรฐานของเครือข่าย)
- ระบบไม่ยอมให้ตั้งส่วนลดเกินจนขายต่ำกว่าต้นทุน

### 6. ทดสอบด้วยยอดเล็ก
1. เติมเบอร์ตัวเอง 10–20 บาท ผ่าน HubZell ทีละเครือข่าย
2. ดู **Log → การเชื่อมต่อผู้ให้บริการ**: ต้องมีคำขอ, คำตอบ และ callback ครบ
3. เช็กเครดิต HubZell ว่าลดลงตรงกับต้นทุนในหน้ารายงาน

## ลูกค้าเลือกร้าน + สลับร้านอัตโนมัติ ทำงานอย่างไร

หน้าเติมเงิน: **กรอกเบอร์ → เลือกค่าย → เลือกร้าน (เห็นส่วนลดของแต่ละร้าน) → เลือกจำนวน (เห็นยอดที่ต้องจ่าย) → ยืนยัน**

| สถานการณ์ | ระบบทำอย่างไร |
|---|---|
| ร้านที่เลือกรับรายการ | ร้านนั้นทำรายการ ลูกค้าจ่ายราคาของร้านนั้น |
| ร้านที่เลือก **ปฏิเสธก่อนทำรายการ** (เครดิตร้านหมด, ปิดปรับปรุง, ต่อไม่ติด, บัญชีมีปัญหา) | ส่งต่อร้านอื่นอัตโนมัติ **ในราคาเดิมที่ลูกค้าตกลง** — เฉพาะร้านที่ต้นทุนไม่เกินราคานั้น ถ้าไม่มีร้านไหนทำได้ คืนเงินทันที |
| ร้านที่เลือก **ไม่ตอบ / หมดเวลารอ / ระบบร้านขัดข้อง (500) / แจ้งว่าเลขอ้างอิงซ้ำ / ตอบรหัสที่ไม่อยู่ในคู่มือ** | **ไม่ส่งร้านอื่นเด็ดขาด** (ร้านแรกอาจทำไปแล้ว) — HubZell: ส่งซ้ำด้วยเลขที่รายการเดิม (คู่มือยืนยันว่าไม่ตัดเงินซ้ำ) เพื่อรู้ผลจริง แล้วส่งให้แอดมินตรวจถ้ายังไม่รู้ |
| ร้านรับรายการแล้วแต่ผลไม่สำเร็จ | คืนเงินลูกค้า (ครั้งเดียว) ไม่ส่งร้านอื่น |
| ร้านมีปัญหาซ้ำๆ | พักร้านนั้นชั่วคราว (circuit breaker) รายการใหม่ไปร้านอื่นโดยไม่เสียเวลา + แจ้งแอดมิน |
| ร้านที่เคยปฏิเสธ กลับมาแจ้งว่ารับ/สำเร็จ (ยังไม่ได้ส่งร้านอื่น) | ให้ร้านนั้นทำรายการต่อ — ไม่ส่งร้านอื่น ไม่คืนเงิน + แจ้งเตือนแอดมิน |
| ร้านที่เคยปฏิเสธ กลับมาแจ้งว่าสำเร็จ (ส่งร้านอื่นไปแล้ว) | ส่งให้แอดมินตรวจทันที แบบ **ล็อกธง** (อาจเติมซ้ำ 2 ร้าน) — ผลของร้านอื่นล้างธงนี้เองไม่ได้ ต้องให้เจ้าหน้าที่ตรวจแล้วกดยืนยัน |

ทุกครั้งที่ส่งไปแต่ละร้านมีบันทึกในหน้ารายละเอียดรายการ (แอดมิน) — ร้านไหน ครั้งที่เท่าไร ต้นทุนเท่าไร ผลอะไร

### "ปฏิเสธ" แบบไหนที่ระบบยอมส่งร้านอื่น (HubZell)
ระบบส่งร้านอื่นได้ **เฉพาะรหัสข้อผิดพลาดที่คู่มือ HubZell ระบุ และสถานะ HTTP ตรงตามคู่มือเท่านั้น**:
`INSUFFICIENT_BALANCE` (400/403), `MAINTENANCE_MODE` (503), `KYC_NOT_APPROVED`, `RESELLER_DISABLED`, `IP_NOT_WHITELISTED`, `IP_BLOCKED` (403),
`MISSING_CREDENTIALS`, `INVALID_SIGNATURE`, `EXPIRED_TIMESTAMP`, `INVALID_TIMESTAMP_FORMAT` (401), `CURRENCY_NOT_ENABLED` (400), `VALIDATION_ERROR` (400/429), `NOT_FOUND` (404)
— คำตอบอื่นทั้งหมด (รหัสใหม่ที่ไม่รู้จัก, ไม่มีรหัส, HTTP ไม่ตรงคู่มือ, หน้า HTML ของไฟร์วอลล์) ถือว่า "ไม่รู้ผล" เสมอ

### กันโดน HubZell บล็อก IP 24 ชม.
- เจอ "ไม่พบ" (404) ครบ 2 ครั้งใน 5 นาที → ระบบหยุดเรียก HubZell เองชั่วคราว (HubZell บล็อกที่ 5 ครั้ง)
- บริการที่ HubZell ลบไปแล้ว → ปิดการจับคู่นั้นทันทีหลังเจอครั้งแรก
- รายการที่ค้นแล้วไม่พบ 2 ครั้ง → หยุดเช็กอัตโนมัติ ส่งให้แอดมินตรวจ
- ส่งรายการใหม่ไป HubZell พร้อมกันได้ไม่เกิน `HUBZELL_MAX_CONCURRENT` (ค่าเริ่มต้น 2) และเช็กการพักซ้ำก่อนส่งทุกครั้ง — ถ้าบัญชีติด KYC จะเสียไม่เกินจำนวนนี้ต่อรอบ
- การพักตั้งแต่ 5 นาทีขึ้นไป (เช่น KYC 1 ชม., IP ถูกบล็อก 24 ชม.) ถูกบันทึกไว้ — รีสตาร์ทเซิร์ฟเวอร์แล้วยังพักอยู่ (กด "เปิดใช้อีกครั้ง" ในหน้าแอดมินเมื่อแก้แล้ว)
- `HUBZELL_API_URL` ต้องเป็น https และลงท้ายด้วย `/api/v1` ไม่เช่นนั้นระบบจะไม่ส่งคำขอเลย

### ห้ามใช้ร้านทดสอบร่วมกับร้านจริง
`PROVIDERS` ที่มีทั้ง `mock`/`mock2` และเจ้าจริง (เช่น `hubzell,mock`) → **เซิร์ฟเวอร์ไม่ยอมเปิด** (ไม่ว่าจะเปิดด้วย start.bat, npm start หรือ Docker)
เพราะรายการที่ถูกส่งต่อไปร้านทดสอบจะ "สำเร็จ" ทั้งที่ไม่ได้เติมจริง

### ตั้งค่าการเลือกร้าน (หน้าแอดมิน → ตั้งค่า → ผู้ให้บริการ)
- **วิธีเลือกผู้ให้บริการ** (ใช้เมื่อลูกค้าไม่ได้เลือกร้าน เช่น API ร้านค้า): ตามลำดับ หรือ ต้นทุนต่ำสุด
- **สลับไปผู้ให้บริการสำรองอัตโนมัติ**: เปิด/ปิด
- **ลำดับผู้ให้บริการ** และ **ปิดใช้ผู้ให้บริการชั่วคราว**

### ลองในเครื่องก่อน (ไม่เสียเงิน)
ค่าเริ่มต้น `PROVIDERS=mock,mock2` = ร้านทดสอบ A และ B — ลองเลือกร้านได้ทันที
ลองสลับร้าน: หน้าแอดมิน → ผู้ให้บริการ & ร้าน → ร้านทดสอบ B → ทำให้เครดิตหมด (หรือพักร้าน) แล้วสั่งรายการด้วยร้าน B
