# วิธีเชื่อมต่อ WonDD API จริง

> **สถานะ ณ 1 พ.ย. 2569:** WonDD ยังไม่เปิดใช้ API ให้บัญชีนี้ คำขอ "ขอเปิดใช้ API" เลขที่ **HN69110000001** ยังรอตอบกลับ
> WonDD แจ้งในหน้า [API Mobile](https://www.wondd.com/api.php) ว่าต้องยื่นเอกสารสมัครเป็น **Sub Agent** ก่อน (AIS One-2-Call!, Dtac Online, True Move)

ระหว่างรอ ระบบใช้ **โหมดทดสอบ (mock)** ได้ครบทุกฟีเจอร์ โดยไม่มีการเติมเงินจริง

---

## สิ่งที่ต้องได้จาก WonDD

คำขอที่ส่งไปแล้วถามครบ 6 ข้อนี้ ให้เช็กว่าคำตอบมีครบ:

| # | เรื่อง | ใช้ทำอะไรในระบบ |
|---|---|---|
| 1 | ขั้นตอน/เอกสารสมัคร Sub Agent | เปิดสิทธิ์ใช้ API |
| 2 | คู่มือ API + ตัวอย่าง Request/Response + Sandbox | แก้ `src/providers/wondd.js` |
| 3 | รายการเติมเงิน/แพ็กเกจที่ใช้ผ่าน API + ราคาทุน/ส่วนลด | ตั้งรหัสสินค้าและราคาในหน้าแอดมิน |
| 4 | ส่งพร้อมกันได้กี่รายการ / กี่คำขอต่อวินาที | ตั้ง `PROVIDER_CONCURRENCY` และ `PROVIDER_MIN_INTERVAL_MS` |
| 5 | Webhook แจ้งผล / API เช็กสถานะ / กันเติมซ้ำตอน timeout | ตั้ง callback + การเช็กสถานะ |
| 6 | ค่าเปิดบริการ / รายเดือน / เครดิตขั้นต่ำ | วางแผนต้นทุน + ตั้งแจ้งเตือนเครดิตต่ำ |

ข้อมูลที่ต้องได้เพิ่ม: **URL ของ API**, **username / API key / secret**, **IP ของ WonDD ที่จะส่ง callback** และ **IP ของเซิร์ฟเวอร์เรา** ที่ต้องแจ้ง WonDD (ถ้าเขาบังคับ whitelist)

---

## ขั้นตอนเปิดใช้งานจริง

### 1. ใส่ข้อมูลใน `.env`

```ini
PROVIDERS=mock,mock2     # ยังเป็นโหมดทดสอบ จนกว่าจะทำข้อ 3 เสร็จ
PUBLIC_URL=https://www.เว็บของคุณ.com
WONDD_API_URL=https://...        # จากคู่มือ
WONDD_USERNAME=...
WONDD_API_KEY=...
WONDD_API_SECRET=...
WONDD_CALLBACK_SECRET=...        # ถ้า WonDD มีลายเซ็น callback ให้ (ดีที่สุด)
WONDD_CALLBACK_IPS=1.2.3.4       # IP ของ WonDD (แนะนำให้ใส่)
```

### 2. แจ้ง WonDD เรื่อง URL รับผล (callback)

```
https://www.เว็บของคุณ.com/api/provider/callback/wondd?t=<รหัสลับ 40 ตัว>
```

คัดลอก URL **ทั้งเส้น (รวม `?t=...`)** จากหน้าแอดมิน → ตั้งค่า → ผู้ให้บริการ ต้องเป็น **https** และเข้าถึงได้จากอินเทอร์เน็ต
(ระบบแนบ URL นี้ไปกับทุกคำขอเติมเงินให้อัตโนมัติด้วย) — **ห้ามเผยแพร่ URL นี้**

**ระบบป้องกัน callback ปลอม** (กันคนปลอมแจ้ง "ไม่สำเร็จ" เพื่อให้ระบบคืนเงินทั้งที่เติมเข้าแล้ว):

| การยืนยัน callback | ระบบทำอย่างไร |
|---|---|
| ไม่มีรหัส `?t=` / ลายเซ็น / IP ที่อนุญาต | **ปฏิเสธทันที** (HTTP 401/403) |
| มีลายเซ็นถูกต้อง (`WONDD_CALLBACK_SECRET`) | ใช้ผลจาก callback ได้เลย (อ่านเฉพาะข้อมูลใน body ที่ลายเซ็นครอบคลุม) |
| ยืนยันได้แค่ IP หรือรหัสใน URL | **ไม่เชื่อเนื้อหา** — ระบบเช็กสถานะกับ WonDD ซ้ำทันที แล้วใช้ผลจากการเช็กแทน |
| ยืนยันได้แค่ IP/รหัส และ WonDD ไม่มี API เช็กสถานะ | ไม่ขยับเงิน ส่งให้แอดมินตรวจ |
| รายการยังไม่ได้ส่ง (pending) | ไม่นำผลมาใช้ |

### 3. แก้ไฟล์ `src/providers/wondd.js` ตามคู่มือ

แก้เฉพาะจุดที่มีป้าย `[MAP]` ส่วนอื่นไม่ต้องแตะ

| ป้าย | ต้องแก้อะไร | ตัวอย่างสิ่งที่ต้องหาในคู่มือ |
|---|---|---|
| `[MAP] 0` | `MAPPING_VERIFIED = true` **หลังทดสอบแล้วเท่านั้น** | — |
| `[MAP] 1` | ความสามารถของ API | มี API เช็กสถานะ / ยอดเครดิต / รายการสินค้าไหม |
| `[MAP] 2` | path ของแต่ละคำสั่ง | `/api/topup`, `/api/check` ฯลฯ |
| `[MAP] 3` | ตารางรหัสสถานะ → สำเร็จ / ไม่สำเร็จ / กำลังดำเนินการ | `status=1` แปลว่าอะไร |
| `[MAP] 3b` | HTTP 4xx ตอนสั่งเติมที่แปลว่า "ปฏิเสธก่อนทำรายการแน่นอน" (คืนเงินได้) | 400 = ข้อมูลผิด? 401 = รหัสผิด? — รหัสที่ไม่ใส่ / แจ้งว่า "ซ้ำ" = ไม่รู้ผล (ไม่คืนเงิน) |
| `[MAP] 4` | ข้อมูลยืนยันตัวตน + วิธีเซ็นลายเซ็น | MD5 / SHA256 / HMAC, ลำดับฟิลด์ |
| `[MAP] 5` | ชื่อพารามิเตอร์ตอนสั่งเติม/สมัครแพ็กเกจ | `mobile` หรือ `msisdn`, `amount` หรือ `price` |
| `[MAP] 6` | ชื่อฟิลด์ในคำตอบ / callback | `transaction_id`, `ref`, `message` |
| `[MAP] 7` | วิธีตรวจลายเซ็น callback | header ไหน คำนวณจากอะไร |
| `[MAP] 8` | รูปแบบรายการสินค้า (ถ้ามี API) | ชื่อฟิลด์รหัส/ราคา/เครือข่าย |
| `[MAP] 9` | ข้อความที่ต้องตอบกลับ callback | `OK` / `SUCCESS` / JSON |

> ⚠️ **กฎเหล็ก:** อย่าเดารหัสสถานะ โดยเฉพาะตัวเลข (บางระบบ `0` = สำเร็จ บางระบบ `0` = ล้มเหลว)
> สถานะที่ไม่ได้ใส่ในตาราง ระบบจะถือเป็น "ไม่รู้ผล" เสมอ → ไม่คืนเงิน ไม่ส่งซ้ำ แล้วส่งให้แอดมินตรวจ ซึ่งปลอดภัยกว่าการเดาผิด
> ⚠️ ผลเช็กสถานะแบบ **"ไม่พบรายการ"** ต้องเป็น "ไม่รู้ผล" ห้ามแปลเป็น "ไม่สำเร็จ" (รายการอาจยังไม่เข้าระบบ WonDD ตอนที่เช็ก)

**ส่งคู่มือ WonDD ให้ Claude แก้ไฟล์นี้ให้ได้เลย** — แนบไฟล์ PDF หรือข้อความคู่มือมาในแชท

### 4. ตั้งรหัสบริการเติมเงินของแต่ละเครือข่าย

หน้าแอดมิน → สินค้า/เครือข่าย → ช่อง "รหัสบริการเติมเงิน (provider code)" ของ AIS / True / dtac ให้ตรงกับคู่มือ
และตั้ง **ส่วนลดที่ได้จาก WonDD** ให้ตรงสัญญา (ค่าตั้งต้นอ้างอิงหน้าบริการของ WonDD: dtac 3.25%, AIS เงินคืน 1.20%, True 3.25%, True โปรเสริม 5%)

### 5. เปลี่ยนแพ็กเกจตัวอย่างเป็นแพ็กเกจจริง

แพ็กเกจที่ติดป้าย "ตัวอย่าง" มีรหัส `DEMO-...` — **ระบบจะไม่ยอมขายในโหมดจริง** (กันขายของที่ไม่มีอยู่จริง)

- กด **"ลบแพ็กเกจตัวอย่าง"** แล้ว
- กด **"ดึงรายการจาก WonDD"** (ถ้า API มีรายการสินค้า — ของใหม่จะถูกเพิ่มแบบ "ปิดขาย" ให้ตรวจราคาก่อนเปิด) หรือเพิ่มเองทีละรายการด้วยรหัสจากคู่มือ

### 6. เปลี่ยนเป็นโหมดจริง

```ini
PROVIDERS=wondd          # หรือ hubzell,wondd ถ้าใช้ HubZell ด้วย (ดู docs/HUBZELL-INTEGRATION.md)
```

แล้วปิด-เปิดระบบใหม่ หน้าแอดมินจะแสดงป้าย **"ใช้งานจริง (WonDD)"** สีเขียว ถ้ายังตั้งค่าไม่ครบ จะเห็นรายการที่ขาดเป็นสีแดง และ **ระบบจะไม่รับรายการ ไม่ตัดเงินลูกค้า** จนกว่าจะครบ

### 7. ทดสอบด้วยยอดเล็กก่อนเปิดขาย

1. หน้าแอดมิน → ตั้งค่า → กด **"เช็กเครดิต"** ต้องเห็นยอดเครดิต WonDD ถูกต้อง
2. เติมเบอร์ตัวเอง **10 บาท** ทีละเครือข่าย (AIS / True / dtac)
3. สมัครแพ็กเกจราคาถูกที่สุด 1 รายการต่อเครือข่าย
4. ลองเบอร์ผิด/ยอดที่ WonDD ไม่รองรับ → ต้องขึ้น "ไม่สำเร็จ" และคืนเงิน
5. ดู **Log → การเชื่อมต่อผู้ให้บริการ** ทุกรายการต้องมีทั้งคำขอ คำตอบ และ callback
6. เช็กว่าเครดิตที่ WonDD ลดลงตรงกับต้นทุนในหน้ารายงาน

## นโยบายของ WonDD ที่ควรรู้ (จากประกาศในเว็บสมาชิก)

- **AIS 12call และ dtac Happy** ยกเลิกรายการได้ภายใน 24 ชั่วโมง ระบบ WonDD ดึงเงินคืนภายใน 2 นาที – 24 ชั่วโมง และคืนได้ตามยอดคงเหลือในเบอร์เท่านั้น
- **True Move** ช่องทางส่วนลดสูงมีโควตาการดึงเงินคืนต่อวัน หากขึ้น "ไม่อนุมัติดึงเงินคืน" แปลว่าเกินโควตา — WonDD แนะนำช่อง "True Move/H (backup)" หากต้องการระบบที่รองรับการเติมผิดเบอร์
- WonDD มีปิดปรับปรุงเป็นระยะ (มักช่วง 22:00–23:59) — ใช้ปุ่ม **ปิดเครือข่ายชั่วคราว + ข้อความแจ้งลูกค้า** ในหน้าแอดมิน หรือโหมดปิดปรับปรุงทั้งระบบ

เมื่อ WonDD ยืนยันว่าดึงเงินคืนสำเร็จ ให้แอดมินกด **"ยืนยันไม่สำเร็จ / คืนเงิน"** ที่รายการนั้น ระบบจะคืนเงินเข้ากระเป๋าลูกค้า (คืนได้ครั้งเดียวต่อรายการ)
