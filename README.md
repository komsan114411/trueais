# ระบบเติมเงินมือถือ & แพ็กเกจเน็ต — AIS • True • dtac (เชื่อมต่อ WonDD)

ระบบเว็บไซต์ครบชุดสำหรับขายเติมเงินมือถือและแพ็กเกจเน็ต มีหน้าเว็บลูกค้า หลังบ้านแอดมิน กระเป๋าเงิน ประวัติทุกอย่าง
และ API สำหรับเชื่อมกับเว็บไซต์อื่น ออกแบบเน้น **กันเติมซ้ำ กันเงินหาย และใช้งานง่าย**

> ### ⚠️ สถานะการเชื่อมต่อผู้ให้บริการ (ร้าน)
> - **HubZell:** เชื่อมตามคู่มือ API จริงแล้ว ใส่ API key/secret ก็ใช้ได้ — ดู [docs/HUBZELL-INTEGRATION.md](docs/HUBZELL-INTEGRATION.md)
> - **WonDD:** ยังไม่เปิดใช้ API ให้บัญชีนี้ (คำขอ HN69110000001 รอตอบ) — เมื่อได้คู่มือ แก้ `src/providers/wondd.js` ตาม [docs/WONDD-INTEGRATION.md](docs/WONDD-INTEGRATION.md)
> - ใช้ได้หลายร้านพร้อมกัน ลูกค้าเลือกร้านเองได้ ร้านไหนไม่รับรายการ ระบบส่งต่อร้านอื่นอัตโนมัติ
> - ค่าเริ่มต้นเป็น **โหมดทดสอบ 2 ร้าน (ร้านทดสอบ A / B)** ใช้ได้ครบทุกฟีเจอร์โดยไม่มีการเติมเงินจริง

## เริ่มใช้งาน (Windows)

1. ต้องมี **Node.js 22.13 ขึ้นไป** (เครื่องนี้มี v24 แล้ว — ถ้าเก่ากว่านี้ `start.bat` จะแจ้งพร้อมลิงก์ดาวน์โหลด <https://nodejs.org>)
2. คัดลอก `.env.example` เป็น `.env` แล้วเปิดด้วย Notepad ตั้ง `ADMIN_EMAIL` และ `ADMIN_PASSWORD` **ก่อนเปิดระบบครั้งแรก**
   (รหัสผ่านอย่างน้อย 8 ตัว มีทั้งตัวอักษรภาษาอังกฤษและตัวเลข — ถ้าไม่ตั้ง หรือข้ามขั้นนี้ไปเลย ระบบจะสร้าง `.env` และสุ่มรหัสแอดมินให้ แสดงในหน้าจอ และบันทึกไว้ที่ `data/ADMIN-PASSWORD.txt`)
3. ดับเบิลคลิก **`start.bat`** (ครั้งแรกจะติดตั้งแพ็กเกจให้อัตโนมัติ) — ปิดระบบด้วย **Ctrl+C** ในหน้าต่างนั้น
4. เปิดเบราว์เซอร์ตามที่อยู่ที่หน้าต่าง start.bat แสดง (ค่าเริ่มต้น `PORT=3000`)
   - หน้าเว็บลูกค้า: <http://localhost:3000>
   - หลังบ้านแอดมิน: <http://localhost:3000/admin>

แก้ `.env` แล้วต้องปิด-เปิดระบบใหม่ทุกครั้ง • เขียนหมายเหตุท้ายค่าได้ถ้าเว้นวรรคก่อน `#` (เช่น `PORT=3000   # พอร์ตเว็บ`) •
ค่าที่มี ` #` หรือ `$` ให้ครอบด้วย `'...'` (เช่น `ADMIN_NAME='ร้านเบอร์ #1'`)

หรือใช้คำสั่ง:

```bash
npm install
npm start
```

### เปิดไม่ขึ้น?
- หน้าต่าง start.bat จะบอก **บรรทัดเดียว** ว่าผิดที่ค่าไหนใน `.env` เช่น
  `เปิดระบบไม่สำเร็จ: ADMIN_PASSWORD ใน .env: รหัสผ่านต้องมี 8-128 ตัวอักษร … → แก้ไฟล์ .env แล้วเปิด start.bat ใหม่`
- **พอร์ตถูกใช้อยู่** — มักเพราะเปิด start.bat ค้างไว้อีกหน้าต่าง ให้ปิดหน้าต่างนั้น หรือเปลี่ยน `PORT` (และเลขพอร์ตใน `PUBLIC_URL`) เป็นเลขอื่น เช่น 8080
- ค่าที่ผิดรูปแบบแต่ยังเปิดได้ (ตัวเลขพิมพ์ผิด, ตั้งชื่อเดียวกัน 2 บรรทัด, บรรทัดไม่มี `=`) ระบบใช้ค่าเริ่มต้น/บรรทัดล่างสุดแทน และเตือนเป็นบรรทัด `[ตรวจไฟล์ .env]` ใต้กรอบ "ระบบเติมเงินพร้อมใช้งาน"
- ต้องการรายละเอียดทางเทคนิคไว้ส่งให้ผู้พัฒนา → เพิ่มบรรทัด `DEBUG=1` ใน `.env` แล้วเปิดใหม่
- พิมพ์ `npm ...` ใน PowerShell แล้วขึ้นว่า *running scripts is disabled* → พิมพ์ `npm.cmd` แทน `npm` หรือใช้ไฟล์ .bat ด้านล่าง

### ไฟล์ช่วยเหลือ (ดับเบิลคลิกได้เลย ไม่ต้องพิมพ์คำสั่ง)

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `start.bat` | เปิดระบบ (ตรวจรุ่น Node.js, ติดตั้งแพ็กเกจครั้งแรก, สร้าง `.env` ถ้ายังไม่มี) |
| `reset-admin-password.bat` | **ลืมรหัสผ่านแอดมิน** — แสดงรายชื่อแอดมิน ใส่อีเมล/เบอร์ แล้วตั้งรหัสใหม่ (อุปกรณ์ที่ล็อกอินบัญชีนั้นไว้จะถูกออกจากระบบ) |
| `disable-2fa.bat` | **โทรศัพท์ที่ใช้รับรหัส 6 หลักหาย** — ปิดยืนยันตัวตน 2 ชั้นของแอดมินคนนั้น ให้เข้าด้วยรหัสผ่านอย่างเดียว (แล้วควรเปิดใหม่ทันที) |
| `backup-now.bat` | **สำรองฐานข้อมูลทันที** (เช่น ก่อนอัปเดตระบบ) แล้วเปิดโฟลเดอร์ `data\backups` ให้คัดลอกไปเก็บ — ดู [สำรองข้อมูล / กู้คืน](#สำรองข้อมูล--กู้คืน) |

ใช้ได้ทั้งตอนระบบเปิดอยู่และปิดอยู่ และทุกการแก้บัญชีถูกบันทึกในหน้าแอดมิน → Log → การกระทำของแอดมิน
(ถ้าระบบเปิดอยู่ การล็อกชั่วคราวราย IP จากการใส่รหัสผิดจะหายเองใน 15 นาที หรือเมื่อปิด-เปิดระบบใหม่)

## ฟีเจอร์ทั้งหมด

### หน้าเว็บลูกค้า
- สมัครสมาชิก / เข้าสู่ระบบ (เบอร์โทรหรืออีเมล) / แก้ข้อมูล / เปลี่ยนรหัสผ่าน
- **เติมเงินมือถือ** AIS / True / dtac แบบง่าย: **กรอกเบอร์ → เลือกค่าย → เลือกร้าน (เห็นส่วนลดแต่ละร้าน) → เลือกจำนวน (เห็นยอดที่ต้องจ่าย)**
- **เลือกร้านได้** — แต่ละร้านราคาของตัวเอง ร้านที่เลือกไม่รับรายการ ระบบส่งต่อร้านอื่นในราคาเดิมอัตโนมัติ
- **ซื้อแพ็กเกจเน็ต** แยกเครือข่าย/หมวด (รายวัน รายสัปดาห์ รายเดือน โทร+เน็ต)
- **เติมหลายเบอร์พร้อมกัน** (วางรายการทีละบรรทัด ตรวจทุกบรรทัดก่อนตัดเงิน)
- หน้าติดตามสถานะแบบเรียลไทม์ + ไทม์ไลน์ทุกขั้นตอน
- **ประวัติการทำรายการ** กรองตามสถานะ/ประเภท/เครือข่าย/วันที่ ค้นหาด้วยเบอร์หรือเลขที่ ดาวน์โหลด CSV และปุ่ม "เติมซ้ำ"
- **กระเป๋าเงิน**: เติมเงินผ่าน QR พร้อมเพย์ (สร้าง QR อัตโนมัติพร้อมยอด) หรือโอนบัญชี + แนบสลิป, ประวัติเติมเงิน, สมุดบัญชีเข้า-ออกทุกรายการ
- **สมุดโทรศัพท์** บันทึกเบอร์ที่เติมบ่อย เลือกได้ทันทีตอนเติม
- **ยืนยันตัวตน 2 ชั้น** (รหัส 6 หลักจากแอป Google Authenticator) และดู/ออกจากระบบ **อุปกรณ์ที่เข้าสู่ระบบอยู่** ได้เอง
- รองรับมือถือเป็นหลัก และโหมดมืด (ตามเครื่อง)

### หลังบ้านแอดมิน
- **แดชบอร์ด**: ยอดขาย กำไร อัตราสำเร็จ วันนี้/เดือนนี้, กราฟ 14 วัน, แยกตามเครือข่าย, รายการล่าสุด, การแจ้งเตือน, เครดิตคงเหลือที่ผู้ให้บริการ, **รายการตรวจความปลอดภัย** (เตือนค่าตั้งที่เสี่ยง แอดมินที่ยังไม่เปิด 2 ชั้น ไม่มีไฟล์สำรอง ฯลฯ)
- **รายการทั้งหมด**: ค้นหา/กรอง/ส่งออก CSV, ดูรายละเอียดทุกขั้นตอน รวมถึงคำขอ-คำตอบดิบจาก WonDD
- **รายการรอตรวจสอบ**: เช็กสถานะซ้ำ, ยืนยันสำเร็จ, ยืนยันไม่สำเร็จ + คืนเงิน
- **อนุมัติเติมเงินเข้ากระเป๋า**: ดูสลิป อนุมัติ (แก้ยอดได้) / ไม่อนุมัติพร้อมเหตุผล
- **ผู้ใช้**: ค้นหา, ปรับยอดเงิน (ต้องระบุเหตุผล กดซ้ำไม่ปรับซ้ำ), ตั้งวงเงินต่อวันรายคน, ระงับบัญชี, ให้สิทธิ์แอดมิน, รีเซ็ตรหัสผ่าน, รีเซ็ตการยืนยัน 2 ชั้น (ลูกค้าทำโทรศัพท์หาย)
- **ตรวจบัญชี**: ยอดกระเป๋าทุกคนเทียบสมุดบัญชี + ตรวจรายรายการว่าเงินที่เก็บจริงตรงกับสถานะ
- **เครือข่ายและแพ็กเกจ**: เปิด/ปิดแต่ละเครือข่าย + ข้อความแจ้งลูกค้า, ยอดเติมต่ำสุด/สูงสุด, ปุ่มยอดเติม, ส่วนลดลูกค้า/ส่วนลดที่ได้, เพิ่ม/แก้/ลบแพ็กเกจ, ดึงรายการจาก WonDD
- **ผู้ให้บริการ & ร้าน**: สถานะ/เครดิตของทุกร้าน, ลำดับและวิธีเลือกร้าน, พัก/เปิดร้าน, ชื่อร้านและส่วนลดของแต่ละร้าน, ดึงรายการ HubZell + จับคู่บริการ (กันขาดทุนอัตโนมัติ), ดูว่าแต่ละรายการส่งไปร้านไหนบ้าง
- **รายงานยอดขาย** รายวัน/รายเดือน/เครือข่าย/สินค้า/ลูกค้า/ช่องทาง + CSV
- **Log**: การเชื่อมต่อผู้ให้บริการ, การกระทำของแอดมิน (audit), webhook, สมุดบัญชีรวม
- **API ร้านค้า**: สร้าง/ยกเลิก API key, จำกัด IP, ตั้ง webhook
- **ตั้งค่า**: ชื่อเว็บ ประกาศ ช่องทางติดต่อ ปิดปรับปรุงระบบ พร้อมเพย์ บัญชีธนาคาร ค่าป้องกันความผิดพลาดทั้งหมด

### เชื่อมกับเว็บไซต์อื่น
- REST API `/api/v1` สำหรับเว็บไซต์ที่มีอยู่แล้ว (PHP, WordPress, Laravel ฯลฯ) + webhook แจ้งผลพร้อมลายเซ็น — ดู [docs/API.md](docs/API.md)
- ฝังหน้าเว็บใน iframe ได้ (ตั้ง `FRAME_ANCESTORS` ใน `.env`)

### แจ้งเตือนแอดมิน (ไม่บังคับ)
LINE Messaging API หรือ Telegram เมื่อ: รายการต้องตรวจสอบ, ผลขัดแย้ง, เครดิตที่ร้านต่ำ, ระบบปลายทางล่ม, มีสลิปรอตรวจ — วิธีตั้งค่าดู [ตั้งค่าแจ้งเตือน LINE / Telegram](#ตั้งค่าแจ้งเตือน-line--telegram)

## ระบบป้องกันความผิดพลาด

| ความเสี่ยง | ระบบป้องกันอย่างไร |
|---|---|
| ลูกค้ากดปุ่มซ้ำ / เน็ตหลุดแล้วส่งใหม่ | ทุกคำสั่งมี **idempotency key** — ส่งซ้ำได้รายการเดิม ตัดเงินครั้งเดียว |
| เติมเบอร์เดิมยอดเดิมซ้ำโดยไม่ตั้งใจ | เตือนตั้งแต่หน้ายืนยัน และต้องกดยืนยันอีกครั้ง (ตั้งช่วงเวลาได้) |
| พิมพ์เบอร์ผิด / เลือกเครือข่ายผิด | ตรวจรูปแบบเบอร์, แสดงเบอร์ตัวใหญ่ในหน้ายืนยัน, ต้องติ๊กยืนยันก่อนกดจ่าย |
| ร้านตอบช้า / timeout / ระบบร้านขัดข้องหลังส่งไปแล้ว | **ไม่คืนเงิน ไม่ส่งซ้ำ ไม่ส่งร้านอื่น** ระบบเช็กสถานะกับร้านเดิมอัตโนมัติ (10 วิ → 1 ชม.) แล้วส่งให้แอดมินตรวจ |
| ร้านที่เลือกปฏิเสธ / ต่อไม่ติด / เครดิตร้านหมด | มั่นใจว่ายังไม่ได้ทำรายการ → **ส่งต่อร้านอื่นอัตโนมัติในราคาเดิม** (ไม่ขาดทุน) ถ้าไม่มีร้านไหนทำได้ คืนเงินทันที |
| เติมซ้ำ 2 ร้าน | ส่งต่อได้เฉพาะรหัสปฏิเสธที่คู่มือระบุ (คำตอบแปลก/ไม่รู้จัก = ไม่รู้ผล ห้ามส่งต่อ), ไม่รู้ผล → ส่งซ้ำด้วยเลขเดิมกับร้านเดิม (ไม่ตัดเงินซ้ำ), บันทึกทุกครั้งที่ส่ง, ผลที่มาช้าจากร้านก่อนหน้าไม่ถูกนำมาใช้, ร้านที่เคยปฏิเสธแต่แจ้งว่าสำเร็จ → ให้ร้านนั้นทำต่อ หรือ **ล็อกธงให้แอดมินตรวจ** ถ้าส่งร้านอื่นไปแล้ว (ทดสอบยิงพร้อมกัน 60 รายการ 2 ร้าน ไม่ซ้ำแม้แต่รายการเดียว) |
| ร้านมีปัญหาซ้ำๆ / ตั้งค่าบัญชีร้านผิด | **พักร้านนั้นอัตโนมัติ** รายการใหม่ไปร้านอื่น + แจ้งแอดมิน (HubZell: หยุดทันทีเมื่อเจอปัญหา KYC/IP/key, จำกัดจำนวนส่งพร้อมกัน, หยุดเรียกเองเมื่อเจอ 404 ซ้ำ กันโดนบล็อก IP 24 ชม. — การพักนานยังอยู่แม้รีสตาร์ท) |
| ปนร้านทดสอบกับร้านจริง | `PROVIDERS` ที่มี mock/mock2 ปนกับเจ้าจริง → เซิร์ฟเวอร์ไม่ยอมเปิด (กันรายการไปเข้าร้านทดสอบแล้ว "สำเร็จ" ทั้งที่ไม่ได้เติม) |
| เครื่องดับ/รีสตาร์ทระหว่างทำรายการ | สถานะถูกบันทึกก่อนส่งทุกครั้ง เปิดใหม่แล้วกู้รายการต่อได้ถูกต้อง |
| คืนเงินซ้ำ / อนุมัติสลิปซ้ำ | ฐานข้อมูลบังคับ "คืนได้ครั้งเดียวต่อรายการ" (unique index) |
| ยอดเงินติดลบ / ตัดเงินพร้อมกัน | ตัดเงินแบบมีเงื่อนไขใน transaction + ฐานข้อมูลห้ามยอดติดลบ |
| ผลขัดแย้ง (คืนเงินแล้ว แต่ภายหลังแจ้งว่าสำเร็จ) | แจ้งแอดมินทันที ไม่ขยับเงินเอง แอดมินกดแก้ได้ในคลิกเดียว |
| callback ปลอม (แจ้ง "ไม่สำเร็จ" เพื่อให้คืนเงิน) | callback ต้องมีลายเซ็น / IP ที่อนุญาต / รหัสลับใน URL ไม่งั้นปฏิเสธ — ถ้าไม่มีลายเซ็น ระบบ **เช็กสถานะกับ WonDD ซ้ำก่อนขยับเงิน** และไม่รับผลของรายการที่ยังไม่ได้ส่ง |
| ราคาเปลี่ยนระหว่างลูกค้ากดยืนยัน | ส่งราคาที่ลูกค้าเห็นไปด้วย ถ้าไม่ตรง **ไม่ตัดเงิน** ให้ยืนยันใหม่ |
| ขายขาดทุนเพราะตั้งราคาผิด / ผู้ให้บริการขึ้นราคา | ห้ามตั้งส่วนลดลูกค้าเกินส่วนลดที่ได้ / ห้ามต้นทุนเกินราคาขาย / ดึงราคาใหม่แล้วต้นทุนเกินราคาขาย → **ปิดขายอัตโนมัติ + แจ้งแอดมิน** |
| ขายแพ็กเกจที่ไม่มีจริง | แพ็กเกจตัวอย่างขายไม่ได้ในโหมดจริง |
| ตั้งค่า WonDD ผิด/ไม่ครบ | โหมดจริงไม่รับรายการจนกว่าจะครบ + ไม่เดารหัสสถานะ (สถานะที่ไม่รู้จัก / แจ้งว่าซ้ำ = ไม่คืนเงิน ให้แอดมินตรวจ) |
| สลิปใบเดียวใช้หลายครั้ง / ยอดโอนซ้ำกัน | ตรวจลายนิ้วมือไฟล์สลิป (ใช้ซ้ำไม่ได้), ระบบสุ่มเศษสตางค์ไม่ให้ซ้ำกับรายการรอตรวจและที่เพิ่งอนุมัติ, เตือนแอดมินเมื่อยอดซ้ำ, อนุมัติแบบไม่มีสลิป/ยอดเกินที่แจ้งต้องยืนยันพร้อมเหตุผล |
| แอดมินกดผิด / กดซ้ำ / 2 คนกดพร้อมกัน | ปรับยอดกดซ้ำไม่ปรับซ้ำ, ระบบปฏิเสธถ้าสถานะเปลี่ยนไปแล้วจากที่เห็นบนจอ, ห้ามสรุปผลรายการที่กำลังรอคำตอบ, รายการที่เพิ่งส่งต้องยืนยันซ้ำก่อนคืนเงิน |
| ถูกโจมตีเดารหัสผ่าน | ใส่ผิด 5 ครั้ง → ล็อกเฉพาะ IP นั้น (เจ้าของยังเข้าได้จากที่อื่น), ผิดรวม 30 ครั้ง → ล็อกทั้งบัญชี + แจ้งแอดมิน, ห้ามรหัสผ่านยอดนิยม, ยืนยันตัวตน 2 ชั้น |
| เซสชันถูกขโมย | แอดมินไม่ได้ใช้งาน 12 ชม. ต้องล็อกอินใหม่, ล็อกอินมีอายุสูงสุด 30 วัน, ใส่รหัสผ่านปัจจุบันผิด 5 ครั้ง = ออกจากระบบทันที, ดู/ออกจากระบบอุปกรณ์อื่นได้ |
| ใช้ระบบเราเจาะเครือข่ายภายใน (SSRF) | webhook / callback_url ของร้านค้าห้ามชี้ localhost / IP ภายใน (ตรวจซ้ำตอนเชื่อมต่อจริง) |
| ยิงคำขอรัวๆ | จำกัดความถี่ทุก API (รวมเติมหลายรายการ), วงเงินต่อวันต่อคน, จำกัดหน่วยความจำของตัวนับ |
| ความปลอดภัยเว็บ | รหัสผ่านเข้ารหัส scrypt, คุกกี้ HttpOnly, CSRF token, รับเฉพาะ JSON, CSP, กัน XSS/SQL injection |
| ตรวจย้อนหลัง | ทุกรายการมีไทม์ไลน์ + log คำขอ-คำตอบ (ซ่อนรหัสลับ) + บันทึกการกระทำของแอดมิน + ตรวจยอดกระเป๋า/รายรายการเทียบสมุดบัญชี |
| ไฟดับ / ฐานข้อมูลเสีย / ลบผิด | บันทึกลงดิสก์ทุกครั้งที่ยืนยันรายการ (ไฟดับไม่ส่งซ้ำ), สำรองอัตโนมัติวันละครั้ง เก็บย้อนหลัง 14 วัน (ดู [สำรองข้อมูล / กู้คืน](#สำรองข้อมูล--กู้คืน)) |

## เบอร์ทดสอบ (เฉพาะโหมดทดสอบ)

ดูจาก 4 หลักท้ายของเบอร์ปลายทาง:

| ลงท้าย | ผลที่จำลอง |
|---|---|
| `0000` | ผู้ให้บริการปฏิเสธ → ไม่สำเร็จ + คืนเงิน |
| `1111` | timeout หลังส่ง → ระบบเช็กสถานะเองแล้วพบว่าสำเร็จ (ไม่คืนเงินผิด) |
| `2222` | ค้างสถานะ → ส่งให้แอดมินตรวจสอบ |
| `3333` | รับเรื่องแล้ว ภายหลังแจ้งไม่สำเร็จผ่าน callback → คืนเงิน |
| `4444` | เชื่อมต่อไม่ได้ → คืนเงินทันที |
| `5555` | รับเรื่องแล้ว ภายหลังแจ้งสำเร็จผ่าน callback |
| อื่นๆ | สุ่มตามค่าในหน้าแอดมิน → ตั้งค่า → โหมดทดสอบ |

เติมเงินให้ลูกค้าทดสอบได้ที่หลังบ้าน → ผู้ใช้ → ปรับยอดเงิน

## ตั้งค่าแจ้งเตือน LINE / Telegram

ระบบส่งข้อความหาแอดมินเมื่อมีเรื่องต้องดู เช่น รายการต้องตรวจสอบ, มีสลิปรอตรวจ, เครดิตที่ร้านเหลือน้อย, ร้านถูกพักอัตโนมัติ, ต้นทุนสูงกว่าราคาขาย, มีคนเดารหัสผ่าน
(เรื่องเดิมไม่ส่งซ้ำถี่ๆ และทุกข้อความถูกเก็บในหน้าแอดมิน → Log เสมอ แม้ยังไม่ได้ตั้งช่องทางไหน) — ตั้งช่องทางเดียวหรือทั้งสองก็ได้ ค่าทั้งหมดอยู่ใน `.env`

### LINE (Messaging API)
> LINE Notify ปิดบริการไปแล้วในปี 2568 (2025) — token ของ LINE Notify ใช้ไม่ได้ ระบบนี้ส่งแบบ **push ผ่าน LINE Official Account (Messaging API)**
> ต้องใส่ทั้ง `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_TO`

1. เข้า <https://manager.line.biz> ด้วยบัญชี LINE → สร้าง **LINE Official Account** (ฟรี)
2. ในหน้าบัญชีนั้น → **ตั้งค่า (Settings) → Messaging API → เปิดใช้ Messaging API** (สร้าง/เลือก Provider ตามที่ถาม)
3. เข้า <https://developers.line.biz/console> → เลือก Provider → channel ของบัญชีนั้น → แท็บ **Messaging API** →
   หัวข้อ **Channel access token (long-lived)** กด **Issue** → คัดลอกไปใส่ `LINE_CHANNEL_ACCESS_TOKEN`
4. แท็บ **Basic settings** → เลื่อนลงหา **Your user ID** (ขึ้นต้นด้วย `U` ยาว 33 ตัว) → ใส่ `LINE_TO`
5. เปิดแอป LINE สแกน QR code ในแท็บ Messaging API เพื่อ **เพิ่มบัญชีทางการนั้นเป็นเพื่อน** (ไม่อย่างนั้นข้อความส่งไม่ถึง)

- ส่งเข้ากลุ่ม LINE: `LINE_TO` ต้องเป็น Group ID (ขึ้นต้นด้วย `C`) ซึ่งดูได้จาก webhook ตอนเชิญบัญชีเข้ากลุ่มเท่านั้น (ระบบนี้ไม่มีตัวรับ webhook ของ LINE) — ถ้าต้องการแจ้งหลายคน ใช้กลุ่ม Telegram ง่ายกว่า
- แพ็กเกจฟรีของ LINE OA ส่งข้อความได้จำนวนจำกัดต่อเดือน (ข้อความ push นับรวมในโควตา) ดูยอดคงเหลือได้ใน LINE Official Account Manager

### Telegram
> ต้องใส่ทั้ง `TELEGRAM_BOT_TOKEN` และ `TELEGRAM_CHAT_ID`

1. ในแอป Telegram ค้นหา **@BotFather** → พิมพ์ `/newbot` → ตั้งชื่อ และ username ที่ลงท้ายด้วย `bot` → ได้ token เช่น `123456789:AAF...` → ใส่ `TELEGRAM_BOT_TOKEN`
2. เปิดแชตกับบอทที่เพิ่งสร้าง กด **Start** (บอทส่งหาเราก่อนไม่ได้)
3. เปิดเบราว์เซอร์ในเครื่องตัวเองไปที่ `https://api.telegram.org/bot<token>/getUpdates` (แทน `<token>` ด้วย token จริง) →
   หา `"chat":{"id":123456789` → ตัวเลขนั้นใส่ `TELEGRAM_CHAT_ID`
   - ส่งเข้ากลุ่ม: เชิญบอทเข้ากลุ่ม พิมพ์ในกลุ่ม เช่น `/start@ชื่อบอท` แล้วเปิด getUpdates ใหม่ — id ของกลุ่มเป็นเลขติดลบ (เช่น `-1001234567890`) ใส่ทั้งเครื่องหมายลบ
   - ถ้าเห็น `"result":[]` ให้ส่งข้อความหาบอทอีกครั้งแล้วรีเฟรช
4. ห้ามเผยแพร่ token (ใครได้ token ไปก็สั่งบอทได้)

### ทดสอบ
ตัวอย่างใน `.env` (แก้บรรทัดที่มีอยู่แล้ว):
```ini
LINE_CHANNEL_ACCESS_TOKEN=token-จาก-LINE
LINE_TO=U0123456789abcdef0123456789abcdef
TELEGRAM_BOT_TOKEN=123456789:AAF...
TELEGRAM_CHAT_ID=123456789
```
บันทึก `.env` → **ปิด-เปิดระบบใหม่** → หน้าแอดมิน → ตั้งค่า → กด **ส่งข้อความทดสอบ** แล้วดูว่าโทรศัพท์ได้รับข้อความ
(หรือสั่ง `npm run admin -- notify-test` ซึ่งอ่าน `.env` ล่าสุดได้เลยโดยไม่ต้องปิด-เปิดระบบ และบอกสาเหตุที่พบบ่อย เช่น token ผิด / ยังไม่ได้เพิ่มเพื่อน / chat id ผิด)

## ขึ้นระบบจริง (Production)

1. เช่า VPS (Ubuntu) หรือ hosting ที่รัน Node.js ได้ แล้วใช้ **HTTPS** เสมอ (Nginx/Caddy + Let's Encrypt หรือ Cloudflare)
2. ตั้ง `.env`:
   - `PUBLIC_URL=https://โดเมนจริง`
   - `TRUST_PROXY=loopback` (Nginx อยู่เครื่องเดียวกัน) หรือ `loopback,uniquelocal` (ใช้ docker-compose) — ตั้งเป็นตัวเลขก็ได้ ระบบจะเชื่อเฉพาะ proxy ในเครือข่ายภายใน (คนนอกปลอม IP ไม่ได้) / ถ้าใช้ Cloudflare โดยไม่มี Nginx ให้ใส่วง IP ของ Cloudflare
   - หลังสร้างแอดมินแล้ว **ลบ `ADMIN_PASSWORD` ออกจาก `.env`**
3. รันด้วย Docker (ดู [รันด้วย Docker](#รันด้วย-docker) — พอร์ตเปิดเฉพาะในเครื่อง ให้ Nginx เป็นตัวรับจากภายนอก, ข้อมูลอยู่ใน `./data`) หรือ PM2: `pm2 start src/server.js --name topup --node-args="--disable-warning=ExperimentalWarning"` — **รันแค่ 1 ตัว** (ห้ามใช้ cluster หลาย process)
4. ล็อกอินแอดมิน → เปิด **ยืนยันตัวตน 2 ชั้น** ที่หน้า "บัญชีของฉัน" และดู **รายการตรวจความปลอดภัย** บนแดชบอร์ดให้หมด
5. ระบบ **สำรองฐานข้อมูลอัตโนมัติวันละครั้ง** ไว้ที่ `data/backups` (เก็บย้อนหลัง 14 วัน) — ควรดาวน์โหลด/คัดลอกไปเก็บนอกเครื่องด้วย ดู [สำรองข้อมูล / กู้คืน](#สำรองข้อมูล--กู้คืน)
6. ตั้ง [แจ้งเตือน LINE / Telegram](#ตั้งค่าแจ้งเตือน-line--telegram) ให้รู้ทันทีเมื่อมีรายการต้องตรวจสอบ
7. ทำตาม [docs/HUBZELL-INTEGRATION.md](docs/HUBZELL-INTEGRATION.md) (ร้านที่ใช้ HubZell อย่างเดียวตั้ง `PROVIDERS=hubzell`) และ [docs/WONDD-INTEGRATION.md](docs/WONDD-INTEGRATION.md) เมื่อ WonDD เปิด API แล้ว

## รันด้วย Docker

ใช้ `docker-compose.yml` ที่มากับระบบ (บริการชื่อ `topup` ข้อมูลทั้งหมดเก็บในโฟลเดอร์ `./data` ของเครื่อง):

```bash
cp .env.example .env              # แล้วแก้ค่าใน .env ให้ครบก่อน
mkdir -p data
docker compose up -d --build      # สร้างและเปิดระบบ (เปิดใหม่อัตโนมัติเมื่อเครื่องรีสตาร์ท)
docker compose logs -f topup      # ดูว่าเปิดสำเร็จไหม (Ctrl+C = เลิกดู ระบบยังทำงานต่อ)
```

- เว็บเปิดที่ `http://127.0.0.1:3000` เฉพาะในเครื่อง — ให้ Nginx/Caddy รับจากอินเทอร์เน็ตพร้อม HTTPS แล้วตั้ง `TRUST_PROXY=loopback,uniquelocal` และ `PUBLIC_URL=https://โดเมนของคุณ`
- ในคอนเทนเนอร์ใช้พอร์ต 3000 เสมอ (`PORT` ใน `.env` ไม่มีผล) — ถ้าจะเปลี่ยนพอร์ตภายนอก แก้บรรทัด `ports:` ใน `docker-compose.yml` เช่น `"127.0.0.1:8080:3000"`
- แก้ `.env` แล้วสั่ง `docker compose up -d` อีกครั้ง (`docker compose restart` ไม่อ่าน `.env` ใหม่)
- คำสั่งแอดมิน: `docker compose exec topup node --disable-warning=ExperimentalWarning scripts/admin.js list` (เปลี่ยน `list` เป็นคำสั่งอื่นในตาราง [คำสั่งที่ใช้บ่อย](#คำสั่งที่ใช้บ่อย) ได้ เช่น `backup`)
- log ขึ้นว่าเปิดฐานข้อมูลไม่ได้ (permission denied) → โฟลเดอร์ `data` ต้องเขียนได้โดยผู้ใช้ในคอนเทนเนอร์: `sudo chown -R 1000:1000 data`
- ปิดระบบ: `docker compose down` (ข้อมูลใน `./data` ไม่หาย)
- ใช้ `docker compose` เท่านั้น — `docker run --env-file .env` อ่านหมายเหตุท้ายบรรทัดและเครื่องหมายคำพูดใน `.env` ไม่เหมือนกัน ค่าจะผิด

## สำรองข้อมูล / กู้คืน

ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ **`data`**: `data/topup.db` (ฐานข้อมูล — ผู้ใช้ ยอดเงิน รายการ ตั้งค่า) และ `data/uploads` (ไฟล์สลิป)

### สำรอง
- ระบบสำรองฐานข้อมูลให้ **อัตโนมัติวันละครั้ง** ไว้ที่ `data/backups` ชื่อไฟล์ตามวันเวลาไทย เช่น `topup-2026-11-02-0930.db`
  — เก็บ **ชุดล่าสุดของแต่ละวันย้อนหลัง 14 วัน + 10 ชุดล่าสุด** (นับรวมชุดที่กดสำรองเอง) ที่เก่ากว่านั้นถูกลบอัตโนมัติ
- สำรองทันที (ทำได้ขณะระบบเปิดอยู่): ดับเบิลคลิก **`backup-now.bat`** หรือหน้าแอดมิน → ตั้งค่า → **สำรองตอนนี้** หรือ `npm run admin -- backup`
- ไฟล์สำรองอยู่ในเครื่องเดียวกับระบบ — **เก็บสำเนานอกเครื่องเป็นประจำ** (แฟลชไดรฟ์ / Google Drive) เผื่อเครื่องเสีย:
  กด **ดาวน์โหลด** ที่ไฟล์สำรองในหน้าแอดมิน → ตั้งค่า หรือคัดลอกโฟลเดอร์ `data/backups` และ `data/uploads`
  (ไฟล์สำรองมีแต่ฐานข้อมูล ไม่รวมไฟล์สลิปใน `data/uploads`)

### กู้คืนจากไฟล์สำรอง
1. **ปิดระบบก่อน** — กด Ctrl+C ในหน้าต่าง start.bat (Docker: `docker compose stop`)
2. (แนะนำ) เก็บของเดิมไว้เผื่อ: สร้างโฟลเดอร์ `data/old` แล้วย้าย `topup.db` พร้อม `topup.db-wal` และ `topup.db-shm` (ถ้ามี) ไปไว้ในนั้น
3. คัดลอกไฟล์สำรองที่เลือกจาก `data/backups` มาไว้ที่ `data/` แล้วเปลี่ยนชื่อเป็น **`topup.db`** (ทับไฟล์เดิม)
4. ตรวจว่าใน `data/` **ไม่มี `topup.db-wal` และ `topup.db-shm` เหลืออยู่** — ถ้ามีให้ลบ (เป็นของฐานข้อมูลเก่า ถ้าทิ้งไว้ข้อมูลจะปนกันจนเสีย)
5. ถ้าไฟล์สลิปหายด้วย คัดลอกโฟลเดอร์ `uploads` ที่สำรองไว้กลับมาที่ `data/uploads`
6. เปิดระบบใหม่ (start.bat / `docker compose start`) แล้วตรวจยอดด้วย `npm run admin -- reconcile`

> ⚠️ ข้อมูลหลังเวลาที่สำรองจะไม่มีในไฟล์สำรอง (รายการเติม, เงินเข้ากระเป๋า, สมาชิกใหม่) — เทียบกับประวัติที่ร้าน (HubZell/WonDD) และสลิปช่วงเวลานั้น
> เพราะรายการที่ส่งไปแล้วอาจเติมสำเร็จจริง แม้ฐานข้อมูลที่กู้คืนจะไม่มีรายการนั้น

## คำสั่งที่ใช้บ่อย

| คำสั่ง | ทำอะไร |
|---|---|
| `npm start` | เปิดระบบ |
| `npm run dev` | เปิดระบบแบบรีโหลดอัตโนมัติเมื่อแก้โค้ด |
| `npm test` | รันชุดทดสอบอัตโนมัติ (กว่า 100 กรณี รวมกรณีเสี่ยงทั้งหมดข้างบน + HubZell จำลอง (ตอบแปลก/หลุด/404/KYC) + ยิงพร้อมกัน 100 รายการ และ 60 รายการ 2 ร้าน + การอ่านไฟล์ .env) |
| `npm run admin -- list` | ดูรายชื่อแอดมิน |
| `npm run admin -- create --email a@b.com --password <รหัสผ่านที่แข็งแรง>` | สร้างแอดมินเพิ่ม |
| `npm run admin -- reset-password --user a@b.com --password <รหัสผ่านใหม่>` | ลืมรหัสแอดมิน (หรือดับเบิลคลิก `reset-admin-password.bat`) |
| `npm run admin -- unlock --user a@b.com` | ปลดล็อกบัญชีที่ใส่รหัสผิดเกิน — ไม่เปิดบัญชีที่แอดมินระงับไว้ (เพิ่ม `--activate` ถ้าต้องการเปิดด้วย) |
| `npm run admin -- disable-2fa --user a@b.com` | ปิดยืนยันตัวตน 2 ชั้น กรณีโทรศัพท์ที่ใช้รับรหัสหาย (หรือ `disable-2fa.bat`) |
| `npm run admin -- backup` | สำรองฐานข้อมูลทันที (หรือ `backup-now.bat`) |
| `npm run admin -- notify-test` | ทดสอบส่งแจ้งเตือน LINE / Telegram ตามค่าใน `.env` |
| `npm run admin -- reconcile` | ตรวจว่ายอดกระเป๋าทุกบัญชีตรงกับสมุดบัญชี |

`--user` ใส่อีเมลหรือเบอร์โทรก็ได้ (`--email` แบบเดิมยังใช้ได้) • ทุกคำสั่งที่แก้บัญชีถูกบันทึกใน Log การกระทำของแอดมิน (ผู้ทำ = ระบบ, `via: cli`) •
PowerShell ขึ้นว่า *running scripts is disabled* → พิมพ์ `npm.cmd` แทน `npm`

## โครงสร้างโปรเจกต์

```
start.bat              เปิดระบบ (Windows)
reset-admin-password.bat / disable-2fa.bat / backup-now.bat   ไฟล์ช่วยเหลือ (ดับเบิลคลิก)
scripts/admin.js       คำสั่งแอดมิน (npm run admin -- ...)
src/
  server.js            จุดเริ่มระบบ (เปิดไม่สำเร็จ → บอกบรรทัดเดียวว่าต้องแก้ค่าไหนใน .env)
  config.js            อ่านค่า .env (รองรับหมายเหตุท้ายบรรทัด / เครื่องหมายคำพูด) + ตรวจค่า
  db.js                ฐานข้อมูล SQLite (ในตัว Node.js) + ตาราง + ข้อมูลเริ่มต้น
  providers/
    hubzell.js         ตัวเชื่อม HubZell (ตามคู่มือ API จริง ลงลายเซ็น HMAC)
    wondd.js           ← ตัวเชื่อม WonDD (แก้ตามคู่มือจริงที่จุด [MAP])
    mock.js            ร้านทดสอบ A / B สำหรับทดสอบ
    base.js            มาตรฐานกลาง + HTTP + log + แยก timeout/ส่งไม่ถึง
  services/
    orders.js          หัวใจ: สร้างรายการ ตัดเงิน ส่ง รับผล คืนเงิน + ส่งต่อร้านสำรอง
    router.js          เลือกร้านที่ทำรายการได้ (ไม่ขาดทุน / ไม่ถูกพัก / มีเครดิต)
    shops.js           ร้านที่ลูกค้าเลือก + ราคาแต่ละร้าน
    providerMap.js     จับคู่ยอด/แพ็กเกจกับรหัสบริการของ HubZell
    wallet.js          กระเป๋าเงิน + สมุดบัญชี
    catalog.js         เครือข่าย แพ็กเกจ ราคา
    deposits.js        เติมเงินเข้ากระเป๋า (พร้อมเพย์/สลิป)
    worker.js          งานเบื้องหลัง (เช็กสถานะ กู้รายการ webhook ล้างข้อมูล)
    securityCheck.js   รายการตรวจความปลอดภัย (แสดงตอนเปิดระบบ + แดชบอร์ด)
    ...                ผู้ใช้ ตั้งค่า รายงาน API key webhook circuit breaker
  lib/
    netguard.js        กัน webhook ชี้เข้าเครือข่ายภายใน (SSRF)
    totp.js            รหัส 6 หลักสำหรับยืนยันตัวตน 2 ชั้น
    ...                เงิน เบอร์โทร พร้อมเพย์ CSV แจ้งเตือน
  http/                เส้นทาง API + ความปลอดภัย
public/                หน้าเว็บลูกค้า (index.html) และหลังบ้าน (admin.html)
docs/                  คู่มือเชื่อม WonDD และ API ร้านค้า
test/                  ชุดทดสอบอัตโนมัติ
data/                  ฐานข้อมูลและไฟล์สลิป (สร้างอัตโนมัติ — ต้องสำรอง)
```

ฐานข้อมูลเก็บเงินเป็น **สตางค์ (จำนวนเต็ม)** ทั้งหมด เพื่อไม่ให้เกิดเศษทศนิยมเพี้ยน
